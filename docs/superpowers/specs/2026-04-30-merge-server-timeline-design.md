# 合服时间轴可视化系统设计文档

## 一、项目概述

### 1.1 目标
构建一个基于时间轴的游戏合服管理可视化系统，用于验证 AntV X6 在时空数据模型中的应用，后续将移植到 evo-manager 项目。

### 1.2 核心场景
- 游戏服务器合服管理
- 支持链式合服（如 3服→2服→1服 的级联合并）
- 时间维度的回溯查看

### 1.3 技术栈
与 evo-manager 保持一致：
- Vue 3.3.4 + TypeScript 4.5.4
- Vite 3.2.5
- Element Plus 2.2.30
- Tailwind CSS 3.3.1 + SCSS
- Pinia 2.1.3
- AntV X6（图编辑引擎）
- Day.js（时间处理）
- IndexedDB（本地数据存储）

## 二、数据模型

### 2.1 核心实体

```typescript
interface MappingNode {
  id: string;           // 唯一标识
  key: string;          // 泳道标识（服务器ID，如 "1服"）
  value: string;        // 目标服务器ID（当 value === key 时表示独立运行）
  startTime: Date;      // 时间段起点
  endTime: Date | null; // 时间段终点，null 表示"至今"（永久）
  parents: string[];    // 溯源ID，用于记录汇入来源（可选，系统自动计算）
}
```

### 2.2 业务语义

| 场景 | key | value | 含义 |
|------|-----|-------|------|
| 独立运行 | "1服" | "1服" | 1服独立运行 |
| 合入他服 | "1服" | "2服" | 1服已合入2服 |
| 链式合服 | "3服" | "2服" → "1服" | 3服先合入2服，2服后来合入1服 |

### 2.3 数据约束

1. **时间连续性**：同一泳道内，相邻节点的时间段应无缝衔接（前一个 endTime = 下一个 startTime）
2. **无重叠**：同一泳道内，任意两个节点的时间段不能重叠
3. **有效引用**：value 必须指向一个存在的泳道（目标服）

## 三、可视化设计

### 3.1 布局模型

```
┌─────────────────────────────────────────────────────────────┐
│  时间轴标尺                                                  │
│  ├─────┼─────┼─────┼─────┼─────┼─────┼─────┼─────┤          │
├─────────────────────────────────────────────────────────────┤
│  1服 │ [→1服 t1~t2]──────[→2服 t2~∞]────┐                   │
│      │                                  │                   │
│  2服 │ [→2服 t1~∞] ←─────────────────────┘                   │
│      │                                                       │
│  3服 │ [→3服 t1~t3]──[→2服 t3~t4]──┐                         │
│      │                            │                         │
│  4服 │ [→4服 t1~t4]──[→1服 t4~∞]  │                         │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 坐标转换引擎

**X 轴（时间 → 像素）：**
```
x = (node.startTime - globalMinTime) * pixelsPerSecond
```

**Y 轴（泳道 → 像素）：**
```
y = swimlaneIndex * swimlaneHeight + offsetY
```

### 3.3 节点样式

- 矩形节点，宽度 = 时间跨度对应的像素数
- 显示内容：`→{value} | {startTime} ~ {endTime}`
- 颜色区分：
  - 独立运行（value === key）：主色调
  - 已合服（value !== key）：次要色调

### 3.4 连线规则

**演进线（同泳道内）：**
- 连接相邻时间段节点
- 样式：直线或平滑曲线

**汇入线（跨泳道）：**
- 触发条件：node.value !== node.key
- 起点来源：当前节点的 startTime 对应目标泳道中的有效节点
- 终点：当前节点左边缘
- 样式：Bezier 曲线（`connector: 'smooth'`），模拟 Git 合并效果

**链式汇入示例：**
```
3服 → 2服：3服节点汇入2服泳道对应时间段
2服 → 1服：2服节点汇入1服泳道对应时间段
结果：形成 3服 → 2服 → 1服 的级联视觉链
```

### 3.5 泳道折叠

折叠后显示迷你时间线：
- 高度压缩（约 20-30px）
- 保留节点位置标记（细线/点）
- 显示泳道名称和当前状态摘要

## 四、交互设计

### 4.1 数据录入

**表单模式：**
- 字段：Key（服务器）、Value（目标服）、StartTime、EndTime
- 验证：时间连续性、重叠检测

**JSON 编辑器模式：**
- 使用 vue3-ts-jsoneditor
- 直接编辑数据数组
- 实时同步到画布

### 4.2 时间回溯

**时间滑块：**
- 位置：画布底部
- 功能：拖动选择时间点，高亮显示该时刻有效的节点
- 辅助：显示选中时间的快照摘要

**探针参考线：**
- 跟随滑块位置
- 垂直线贯穿所有泳道
- 不跟随鼠标移动（性能考虑）

### 4.3 时间范围过滤

- 工具栏提供时间范围选择器
- 只加载和渲染指定时间段内的数据
- 减少大数据量时的渲染压力

## 五、架构设计

### 5.1 目录结构

```
src/
├── components/
│   ├── Canvas/              # X6 画布
│   │   ├── index.vue        # 画布容器
│   │   ├── Swimlane.vue     # 泳道组件
│   │   ├── Node.vue         # 节点组件
│   │   └── Connection.vue   # 连线渲染
│   ├── TimelineSlider/      # 时间滑块
│   │   └── index.vue
│   ├── DataPanel/           # 数据录入面板
│   │   ├── FormInput.vue    # 表单录入
│   │   └── JsonEditor.vue   # JSON 编辑器
│   └── Toolbar/             # 工具栏
│       ├── TimeFilter.vue   # 时间范围过滤
│       └── SwimlaneManager.vue # 泳道管理（折叠等）
├── stores/
│   └── mapping.ts           # Pinia store
├── utils/
│   ├── timeAxis.ts          # 时间-坐标转换
│   ├── connectionEngine.ts  # 连线计算引擎
│   └── db.ts                # IndexedDB 封装
├── types/
│   └── mapping.ts           # 类型定义
└── data/
    └── seed.json            # 初始种子数据
```

### 5.2 数据流

```
用户录入 → Pinia Store → IndexedDB 持久化
                ↓
          计算属性/Action
                ↓
         X6 画布渲染
```

### 5.3 关键模块职责

| 模块 | 职责 |
|------|------|
| `mapping.ts` (store) | 状态管理、CRUD 操作、IndexedDB 同步 |
| `timeAxis.ts` | 时间与像素坐标双向转换 |
| `connectionEngine.ts` | 根据节点数据计算演进线和汇入线 |
| `db.ts` | IndexedDB 的增删改查封装 |

## 七、性能优化策略

| 策略 | 说明 |
|------|------|
| 时间范围过滤 | 只加载指定时间段的数据，减少渲染节点数 |
| 泳道折叠 | 折叠泳道使用迷你时间线，减少 DOM 元素 |
| 滑块防抖 | 滑块拖动时使用防抖，避免频繁重绘 |
| 虚拟滚动 | 泳道数量过多时，可后续扩展虚拟滚动 |

---

## 八、验收标准

1. **数据录入**：表单和 JSON 编辑器都能正常添加/修改/删除数据
2. **画布渲染**：泳道和节点按时间轴正确布局
3. **连线正确**：演进线和汇入线正确生成，链式合服显示正确
4. **时间回溯**：滑块拖动时正确高亮对应时间点的节点
5. **折叠功能**：泳道折叠后显示迷你时间线
6. **数据持久化**：刷新页面后数据保留
